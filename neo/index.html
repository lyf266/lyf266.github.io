Personal Opportunity Intelligence (POI)

每天自动从几十个信息源里筛出值得看的内容和机会，推送到手机上。

问题

全球官方奖学金（DAAD/Erasmus Mundus）、带薪开源导师（LFX）、黑客松与远程兼职岗位信息极度分散碎片化，人工搜集信噪比低，容易因信息过载陷入决策内耗。

方法
抓取多渠道→加权打分→推送高分

专属机会挖掘与量化决策智能体，全天候并发抓取 9 大维度渠道的官方数据源，自动进行多维打分初筛与价值评估。

工程
Personal Opportunity Int/
├── fetch_feeds.py ── 多源抓取引擎
├── score.py ── 加权打分
├── server.py ── 轻量 HTTP 服务
└── radar.svg ── 机会雷达图

Python 原生轻量 HTTP 服务 (server.py) + 并发多源 RSS/Atom 抓取引擎 (fetch_feeds.py) + Vanilla CSS/JS 响应式单页 + SVG 蛛网雷达图。核心硬约束：独创 7 维加权决策评估公式 (7D Formula)，长期价值/技能/未来帮助加权正向，时间成本/风险控制惩罚扣减；仅加权得分 ≥ 8.0 的机会才触发 Telegram/Notion 深度推送。

结果 / 状态

当前已实现全球官方奖学金、开源项目资助与远程岗位的 7 维加权初筛。后续演进规划：1) 新增针对主流招聘平台的‘AI Agent 与大模型领域优质实习机会’定向抓取与动态匹配模块，精准满足青年开发者在 AI 时代的实习与实战积累需求；2) 引入轻量 LLM 对非结构化长文进行意图重排与岗位信噪比深度过滤。

Personal LifeOS (Project PAI)

帮你管目标、记日志的个人系统，还能定时自动生成复盘报告。

问题

传统对话式 AI 随会话结束而遗忘，长期对话时产生严重的上下文漂移、多会话历史割裂与幻觉，缺乏对用户真实目标的持续跟踪。

方法
记录日志→检索事实→LLM 复盘→决策建议

专属个人长期智能体系统（PAI），持续对“用户自身、客观世界及其相互关系”进行建模。Agent 目标不是问答聊天机器人，而是协助用户进行生活日志复盘、个人目标追踪与决策建议。

工程
Personal LifeOS (Project/
├── api/ ── FastAPI 模块化单体
├── web/ ── Next.js 前端
├── postgres/ ── 规范事实库
└── qdrant/ ── 语义向量检索

FastAPI 模块化单体 + Next.js 前端 + PostgreSQL (规范事实) + Qdrant (语义向量) + OpenRouter/LLM。核心硬约束：Retrieval before reasoning（检索先于推理，显式提取结构化记忆）；高影响动作必须人类确认；内存开销严格限制。

结果 / 状态

Linux Whisper Input

Linux 上好用的全局语音输入法很少，所以自己做了一个：按快捷键说话就变成文字，模型常驻本地，无需联网。

问题

云端听写受制于网络往返延迟（>1s）与隐私泄露隐患；传统本地脚本每次按快捷键都要冷启动加载数 GB 模型，卡顿数秒严重打断输入心流。

方法
按下快捷键→捕获音频→VAD 裁切→本地推理→注入文本

采用 Python + CTranslate2（large-v3-turbo float16）+ PipeWire 管道捕获音频流 + Wayland 虚拟键盘事件注入 + Systemd 用户级守护。模型权重与 CUDA 上下文永久驻留 GPU 显存，快捷键唤醒后直接推理，无需重新加载模型。（延迟数据待系统性实测）

工程
Linux Whisper Input/
├── daemon.py ── 常驻监听
├── vad.py ── 语音端点检测
├── infer.py ── CTranslate2 推理
└── wayland-inject.py ── 文本注入

在模型部署时，我重点优化显存占用和响应速度之间的平衡。通过 VAD 判断有效语音区间，减少无意义音频输入，同时将监听和推理拆分为独立进程，避免任务互相影响。

结果 / 状态

硬件绑定 NVIDIA GPU 显存；对极长语音的停顿分段参数需继续调优。

Desktop TimeTracker (timetrack)

自动记录每天在每个窗口上花了多少时间，生成日报，帮你看清时间都去哪了。

问题

KDE Plasma 6 Wayland 安全沙箱机制阻断了传统 X11 窗口监听工具；市面商业软件（如 RescueTime）多基于臃肿的 Electron 进程（动辄消耗数百 MB 内存）且依赖闭源云端上传隐私数据。

方法
监听窗口→三级识别→本地存储→夜间日报

项目尽量保持轻量化，没有引入额外 Python 第三方依赖。窗口识别采用三级匹配策略：1. 用户自定义规则优先；2. 使用系统应用元数据辅助判断；3. 最后根据进程信息进行兜底。

工程
Desktop TimeTracker (tim/
├── kwin-script.js ── 窗口监听
├── identify.py ── 三级识别
├── store.db ── SQLite 本地存储
└── report.py ── 日报生成

内存与 CPU 占用保持较低（具体数值待实测），全本地存储；夜间自动离线生成图文并茂的 Markdown 时间复盘报告。

结果 / 状态

深度绑定 KDE Plasma 6 Wayland 合成器，跨桌面环境（如 GNOME/Sway）需适配不同合成器 IPC 接口。

OBS Studio 推流与摄像头驱动加固

调好了 Linux 下的推流：画面不再崩溃，还能在直播画面上实时显示时间和待办。

问题

Linux 下 USB 摄像头在默认 MJPG 采集时遇坏包触发 FFmpeg 软件解码崩溃死循环；叠加 WebM 透明动效时 GPU 硬解码（NVDEC）会剥离 alpha 通道导致抠像全黑；OBS 重载场景时坐标漂移到画布中心。

方法
YUYV 直采→绕过软解→叠加信息→推流

锁定未压缩 YUYV 4:2:2 原始像素直采（OBS format 1448695129）完全绕过 FFmpeg 软解；配置 udev 规则禁用 USB autosuspend；双向同步计算 pos 绝对像素与 pos_rel 相对归一化坐标；WebM 强制 libvpx 软解保留 32 位全透明通道；进程内 Lua 定时器驱动动态时间。

工程
OBS Studio Stream & V4L2/
├── yuyv-capture ── 原始像素直采
├── udev.rules ── 禁用 USB 休眠
└── overlay.lua ── 时间/待办叠加

通过减少中间层依赖，降低 USB 采集过程中的丢帧风险。系统不需要额外后台服务，采集和处理流程保持在单一应用内。

结果 / 状态

硬件参数针对特定型号深度加固，跨机使用需根据摄像头 VID/PID 重新绑定 udev 规则。
